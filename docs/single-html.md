# 单文件 HTML 版

`single-html` 分支根目录的 `index.html` 包含完整咖啡小馆流程：首页与随机来单、准备水与粉、冲煮与实时三维结构、单杯调配、双杯实验、特刊编辑和 PNG 导出。源码与本地开发仍保留在 `main` 分支。

## 使用

下载分支中的 `index.html` 后，可尝试用桌面 Chrome 或 Edge 直接打开。图片、模型、样式和脚本都内嵌，无需将 `assets/`、`vendor/` 等目录复制到旁边；也可以把这份文件放到普通静态网页服务器上。三维视图需要浏览器支持 WebGL。

首次打开需解析约 40 MiB 的文件；之后跳转通过同一文件的 `screen` 查询参数选择首页、冲煮或调配。配方、库存、制作进度与特刊册仍依赖当前浏览器的本地存储。不同浏览器、文件位置或网页地址之间不自动共享记录。

PNG 在浏览器中生成并下载，单文件版不请求 `api/export-poster`。它不会像源码版的本地服务一样在服务器 `exports/` 目录生成文件。单文件版不包括历史原型与设计参考页。

## 从源码构建

使用 Node.js，然后在仓库根目录执行：

```sh
npm install
npm run build:single
node qa/single-html-test.mjs
```

生成 `dist/caffe-simulation.html` 和 `dist/single-html-manifest.json`。清单记录完整文件及各内嵌资源的 SHA-256。所有业务模块通过 esbuild 打包，Three.js 的 MIT 许可保留在包内。没有运行时 CDN 依赖；资源加载转换为包内 data URL，普通网络 fetch 在单文件环境中关闭。

## 核验范围

2026-10-11 完整状态与模型测试 12 组通过。单文件资源测试核对三个脚本包语法、43 个内嵌资源、图片与 GLB 内容、字节数和 SHA-256。

浏览器预览使用 `qa/single-html-preview.cjs`：它只提供这一份 HTML，其他路径全部返回 404，防止仓库里的外置资源掩盖打包遗漏。实际完成首页选择、120 g 水 / 18 g 粉冲煮、86.4 g 出液传递、40 g 咖啡液 + 160 g 牛奶 + 两块冰调配、搅拌、分杯、特刊切换、返回调配和查看这锅来源。实际导出 1200 × 1800 PNG 并收入特刊册；最终控制台无警告或错误。预览服务日志只有 HTML 和浏览器 favicon 请求，没有外置资源或导出 API 请求。截图及实际 PNG 输出见 `qa/single-html-review-2026-10-11/`。

当前自动化浏览器不允许访问 `file://`，因此没有自动核验本机双击文件的完整流程。若浏览器禁止本地文件存储，跨页面进度不能可靠保存；此时应将单文件放在普通静态服务器上使用。此限制不需要关闭浏览器安全设置。
